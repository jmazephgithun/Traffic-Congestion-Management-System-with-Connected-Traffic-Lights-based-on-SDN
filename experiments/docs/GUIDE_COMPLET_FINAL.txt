🐛 HISTORIQUE DU DÉBOGAGE
═════════════════════════════════════════════════════════════════════════════════

PROBLÈME INITIAL:
  Adaptive prenait 20h au lieu de 1h
  → Deadlock, véhicules bloqués
  → Throughput ~1-5 veh/h au lieu de ~920 veh/h

CAUSE IDENTIFIÉE:
  L'orchestrateur forçait NS_GREEN (phase 0)
  Mais SUMO utilisait phase 0 pour EW_GREEN!
  → Inversion des phases → tous les véhicules bloqués

SOLUTIONS TESTÉES:
  1. ❌ ULTRA_FIXED: retry agressif → crashait SUMO
  2. ❌ SIMPLE: time.sleep() → déconnexion TraCI
  3. ❌ WORKING: simulationStep() mais logique buggée
  4. ❌ FINAL: connexion OK mais ne switchait jamais de phase
  5. ✅ CORRECTED: connexion + logique corrigée → FONCTIONNE!

LE BUG FINAL:
  L'ancien code gardait 'target_phase' et 'cur_phase' séparés
  → Confusion entre phase désirée et phase réelle
  → Restait bloqué sur phase 0

LA CORRECTION:
  'current_phase' = unique source de vérité
  'should_switch' = décision binaire claire
  'new_phase' = phase cible calculée
  → Alterne correctement entre 0 (NS) et 2 (EW)


🔧 PARAMÈTRES DE L'ORCHESTRATEUR
═════════════════════════════════════════════════════════════════════════════════

Paramètres actuels:
  --ns-phase-idx 0         # Phase pour NS (Nord-Sud) vert
  --ew-phase-idx 2         # Phase pour EW (Est-Ouest) vert
  --min-green 10           # Minimum 10s avant switch
  --max-green 45           # Maximum 45s, puis switch forcé
  --hysteresis 0.15        # 15% d'écart avant switch

Logique de décision:
  Si phase=NS et EW_queue > NS_queue * 1.15 → switch vers EW
  Si phase=EW et NS_queue > EW_queue * 1.15 → switch vers NS
  Si elapsed ≥ 45s → switch forcé (équité)
